Behind the scenes

From two documents to one audit-ready report

Seven deterministic stages sit between the upload and the report. Only the first one needs a person.

01

Upload

A BRD and one or two SDDs; the only human step.

02

Sealed blinding

Lane identities locked in an escrow no one and nothing reads until the final step; judges see only “Output A/B”.

03

Frozen calibration

99 criteria from Zennify’s SDD standard and the Salesforce Well-Architected framework, filtered to the engagement.

04

Dual-judge scoring

Claude and Gemini each score every criterion independently from byte-identical packets, quoting the document verbatim for every verdict.

05

Evidence-ruled consensus

Divergences are reconciled only by pointing at what the SDD actually says; genuine disagreements are preserved as dissents and resolved conservatively, never averaged away.

06

28-rule validation

Every anchor, citation, attestation, and deduction must pass the framework’s validation gate before a report can exist.

07

Sealed reveal & report

The escrow is opened last; the methodology lift is oriented and the branded report is built with a full audit trail.

Guarantees

Blinded until the last step

The lane-identity escrow is written at intake and first read at reveal — never by a judge, never by a route.

Two independent model families

Claude and Gemini score in isolation; dissents are preserved, not averaged away.

Every claim anchored verbatim

Each verdict quotes the exact SDD text it rests on — no claim without an anchor.

Zero API billing

Subscription tokens only, with billing guards and a server tripwire. Reported API cost stays $0.00.
